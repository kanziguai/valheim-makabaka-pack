MAKABAKA v1.19（2026-09-25）

本版 = v1.18 的全部内容 + 自研插件一处【紧急修复】（VRMAliasLink 0.2.0 → 0.2.3，三次修复）+ 一键安装脚本的三处改动。

【修·重要】自研 VRMAliasLink 0.2.0 → 0.2.1：修掉"一开游戏就崩"
- 现象（装了 v1.18 的人现在就是这个样子）：点启动后十几秒进程消失、游戏窗口起不来。
  Windows 事件日志里是 valheim.exe / 错误模块 ntdll.dll / 异常代码 0xc0000005；
  BepInEx 日志停在：[VRMAliasLink] 本地别名表 = …（存在）；订阅 = (未设置)
  —— 再往下那行"广播：发出 = True，接收 = True"永远打不出来。
- 原因：插件里一个属性写成了自引用（表达式体里又读自己），一被读就无限递归 → 栈溢出 → 进程当场死。
  编出来时编译 0 警告、离线自测全绿，照样崩 —— 只有真进一次游戏才能发现。
- 0.2.1：只改那一行，功能与 0.2.0 完全相同。已实测进游戏跑通，日志里能看到
  "Loading [VRM Alias Link 0.2.3]" … "广播：发出 = True，接收 = True（键 vrma_model，每 2 秒一轮）"，
  并成功广播了自己用的模型（[广播] 我用的是「…」（指纹 …，已进同步队列））。
- 顺带加了防回归自检：check-contract.sh 现在会扫"属性自引用"。

【修】自研 VRMAliasLink 0.2.2 → 0.2.3：日志里的版本号写错 / manifest 多一行垃圾表头
- 日志那句"已加载 vX"读的是插件自己的版本号，而 [BepInPlugin] 里写死的还是 "0.2.1" —— 于是出现
  "包里是 0.2.2、日志却说已加载 v0.2.1"（日志是排错的第一现场，标错版本会把人带偏）。
  现在版本号只有一处：源码 Plugin.VersionString，[BepInPlugin] 直接用它；check-contract.sh 会核对它与
  manifest.json 的 version_number 一致，不一致直接报 MISMATCH（同类事故不再复发）。
- 顺带：_别名_manifest.txt 里会多出一行表头 —— 老代码读表时没跳过 # 开头的行，把老版本写的表头当成
  一条玩家记录读了又写回去。已修；被写坏的垃圾行下次保存时会自动消失。
- 0.2.3 与 0.2.2 行为完全相同（只动版本号字符串与读表那段）。
- 双机实测结果（2026-09-25，你自己那两台）：两人成功互看对方模型，跨文件名也对（靠内容指纹）；
  14:14 那局两边各出现一次"已有 <玩家名>.vrm 不是本插件建的，已备份到 …" —— 这是**预期的一次**：
  那两个文件是 0.2.1 落的、manifest 里没有记录，插件只能按"外来文件"备份一次再覆盖。
  0.2.2 起 manifest 会记盘（实测已写入 KaNzIgUaI|无常-必安.vrm|…|hardlink|a82710a3fd284159），
  所以之后每局不会再备份。

【修】自研 VRMAliasLink 0.2.1 → 0.2.2：广播落名没记盘（第二局会白备份一遍对方模型）
- 双机实测（2026-09-25，两人成功互看对方模型）之后核对磁盘才发现：_别名_manifest.txt 里一条落地记录都没有。
- 原因：广播落名那条路径只在"清单行已存在且指纹不同"时才写盘，而落名那一刻该行刚按源文件指纹写进内存
  → 条件恒假 → 从不写盘（别名表那条路径写得是对的，只有广播这条漏了）。
- 后果：下一局插件把自己造的 <玩家名>.vrm 当成"不是本插件建的"外来文件，按"覆盖已有文件"先整份备份一遍
  （几十~几百 MB 进 _别名备份_<时间>\）再覆盖 —— 功能照旧能用，但每局白占一份模型大小的磁盘。
- 0.2.2：改成"真落了名就写盘"，与别名表那条路径一致。自测步骤见插件包里的 本地自测.txt【C】。
【修】选 1 之后不再静默几十秒（v1.18 及更早会）
- 现象：双击 一键安装.bat → 选 1 → 屏幕停在 [1/7] 不动，几十秒到一分钟之后才打出档目录，
  很像卡死（等不及关了窗口，于是感觉"认不到路径"）。
- 原因：第 ③ 步"从 r2modman 自己的记录里翻路径"会递归整个 r2modman 数据文件夹
  （里面装着已安装的档：几千个文件、上百 MB 插件日志），每个文件还被三种编码各扫一遍正则。
- 现在：③ 只翻 r2modman 自己的小文件（不走进 profiles\ / image-cache / _import_cache / cache / exports / node_modules），
  每个文件只读开头 256 KB、只取最近改过的 150 个、总预算 6 秒；翻到"确实存在的 \Valheim\profiles"立刻收工。
- 实测：同一台机器同一场景，选 1 之后 [1/7] → 路径行 25.6 秒 → 1 秒内出结果；找到的目录与
  来源标注（"r2modman 记录过的路径"）跟以前完全一样，行为不变。

【新】多路径识别：C 盘一份、D 盘也一份时，全都列出来让你挑
- 以前只要默认位置/记录里找到一条就不再扫盘 —— 另一块盘那份永远看不见。
- 现在不管前面找没找到，都会再扫一遍所有固定硬盘（最多 12 秒；本机 4 个固定盘实测整趟 1~5 秒），
  找到的数据文件夹全都进候选表：
    1) 里面已经有档的排前面，会标出"已有 MAKABAKA 档（时间）""该数据文件夹里共 N 个档"；
    2) "空壳"（数据文件夹被挪走后留下的 / 还没建过档的）一律排最后。
- 只有一个位置"里面真有档"时不会停下来问你：直接用那份，其它位置只打一行信息。
- 要你挑的时候：直接回车 = 第 1 项（一般就是要升级的那份）；输 9 = 再扫一遍各硬盘；输 0 = 自己粘路径。
- 上次装过的那份永远排第 1（install-path.txt 记着）。

【新】绝不自己新建路径
- 只用机器上【现有】的 r2modman 数据文件夹。解析出来的目标要是不存在（r2modman 还没跑过、
  数据文件夹被挪到别的盘…），脚本直接停下报错，并提示"先装好 r2modman 并启动一次，或用 -ProfilesRoot 指定"，
  不会再偷偷建一个 %APPDATA%\r2modmanPlus-local\Valheim\profiles 出来。
- 唯一例外：你自己明确指定的路径（-ProfilesRoot <路径>，或装的时候自己粘进去的）不存在时，
  才按你说的建出来，并在屏幕上写明"这条路径是你自己指定的、机器上还没有"。

【修】排查开关 -Diag 里"扫各硬盘"那段以前是假的
- 老版本 -Diag 第 ④ 段压根没真扫，永远打印"用时 0 秒 / 没扫到"，会把排查带偏。
- 现在真扫并计时（本机实测 1 秒扫到 C:\Users\...\r2modmanPlus-local\Valheim\profiles）。

升级提示：
- 档内容（mod / 配置 / 模型）与 v1.18 一致，但**插件 dll 换了**（VRMAliasLink 0.2.0 → 0.2.3，三次修复），
